# i18n (en/ja) — SPA での持ち方

MPA 側 (`internal/web/i18n.go`) の解決順は `lang` クッキー >
`Accept-Language` > `en` で、文字列はサーバーテンプレート +
`/static/i18n.js` の messages テーブル。SPA ではレンダリングが全部
クライアント側なので構成が変わる。

## 方針

- **ロケール解決**: `localStorage('lang')` > `navigator.language`
  > `'en'`。cookie → localStorage、Accept-Language →
  navigator.language のそのまま写像 (MPA と同等の意味論)。
  - URL 接頭辞 (`/ja/w/...`) は採らない: ルーター表が 2 倍になり、
    言語は共有 URL より「見ている人の設定」に従うべき情報なので。
    MPA も URL に入れていない。
- **スイッチャ**: nav に小さい言語切替。localStorage に保存 →
  全 UI 即時反映 (`document.documentElement.lang` も同期)。
- **文字列**: ライブラリは入れず、型付き messages 辞書を手書き
  (MPA の `messages` 構造体の写像。`en` を正、`ja: typeof en` で
  キー漏れはコンパイル時に検出)。`t(key)` + `{n}` 埋め込みのみ。
- **API エラー等のサーバー文字列は未翻訳** (MPA 同様)。ユーザーの
  投稿文も未翻訳。
